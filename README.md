# Методы разработки программного обеспечения

Репозиторий с лабораторными работами по дисциплине «Методы разработки программного обеспечения».

## Лабораторная работа №1

Тема: «Метрическая оценка программного обеспечения».

Вариант №6 — каталог автомобилей.

Реализованы три версии программы:

- `lab1/linear.cpp` — линейная версия;
- `lab1/pointers.cpp` — версия с использованием указателей;
- `modular/` — модульная версия.

### Функциональность

Во всех версиях реализованы:

- добавление автомобиля;
- просмотр всех записей;
- поиск по каждому атрибуту;
- хранение данных в бинарном файле;
- выход из программы.

### Структура модульной версии

| Файл | Назначение |
| --- | --- |
| `modular/main.cpp` | Точка входа, меню и вызовы функций |
| `modular/car.h` | Структура `Car`: марка, модель, год, цена, кузов, сегмент |
| `modular/functions.h` | Объявления функций |
| `modular/functions.cpp` | Добавление, просмотр, выбор способа поиска, шесть функций поиска и общий вывод `printCar` |

### Сборка на Windows

Нужен установленный GCC / MinGW-w64 (например, MSYS2 UCRT64).

Распакуйте архив и откройте PowerShell в папке, где находятся `build.ps1` и `run.ps1`.
При скачивании ZIP с GitHub внутри распакованной папки может находиться ещё одна папка проекта.
Путь с пробелами заключайте в кавычки:

```powershell
cd "C:\ПУТЬ\К\ПРОЕКТУ"
```

Если PowerShell запрещает запуск сценариев, разрешите их для текущего окна:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Если MSYS2 установлен в `C:\msys64`, добавьте папку компилятора и его DLL в `PATH` текущего окна:

```powershell
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
```

Для другой установки укажите её фактическую папку `bin`.
Настройки политики и `PATH` в этих командах действуют до закрытия окна; права администратора не требуются.

Соберите три версии:

```powershell
.\build.ps1
```

Успешная сборка заканчивается сообщением `Build completed successfully.`.
Исполняемые файлы создаются в `build`. Повторная сборка нужна после изменения исходников
или если готовые исполняемые файлы отсутствуют.

### Запуск

Чтобы данные трёх реализаций не смешивались в одном `cars.dat`, запуск программ осуществляется через `run.ps1`:

```powershell
.\run.ps1 linear
.\run.ps1 pointers
.\run.ps1 modular
```

Перед запуском следующей версии завершите предыдущую через пункт `0 - Exit`.

Для каждой версии создаётся отдельная рабочая папка в `run-data`, поэтому у каждой программы получается свой собственный `cars.dat`.

### Ручная сборка

```powershell
g++ lab1\linear.cpp -o linear.exe
g++ lab1\pointers.cpp -o pointers.exe
g++ modular\main.cpp modular\functions.cpp -o modular.exe
```
